# Failure signature → fix

| signature | cause | fix |
| --- | --- | --- |
| `Statically allocated dataflow buffers ... clash with L1 buffers`, or `L1 buffer allocated at <A> and static circular buffer region ends at <B>` at a member's compile | another member keeps L1 resident at addresses this member's programs need | turn off the resident member's persistent L1 state (GPT-OSS: `GPT_OSS_20B_FUSED_B1=0`); size this member's programs to fit (`preload` hook, e.g. the distributed prefill norm); `TT_COHOST_L1_REPORT=1` shows who holds what. Two replicas of an L1-heavy model do not fit |
| `TypeError: ... unexpected keyword argument 'new_request_rows'` on a long prompt or a prefix-cache hit (tt_transformers member) | the image's chunked or prefix-cached prefill path forwards plugin kwargs the model does not take | the `preload` fit hook that drops them |
| out of DRAM in the last member's load or warmup | the members' weights + KV pools + trace region exceed the chip | `kv_tokens` caps, a shorter context for one member, a smaller trace region |
| at exit: `pthread_mutex_unlock failed() for mutex CHIP_IN_USE_0_PCIe errno 1` and an abort | tt-metal closes the chips on the main thread at exit, but a non-main device thread took UMD's per-chip lock | run the device loop on the main thread (the co-host runtime does) |
| a 4-chip group fails with `Fabric Router Sync: Timeout ... did not complete the remote (ethernet) handshake`, or hangs in the first all-reduce | an earlier dirty stop reset only some chips | reset every chip once nothing uses them; a current `tt-model stop` resets the chips nothing holds |
| a start sits for tens of minutes in `ttnn.as_tensor` / `ttnn.load_tensor` at 100 % system time (system time far above user time, minor faults climbing, the fd open on one `.tensorbin`) | on some hosts a tensor-cache file read soon after it was written hangs: a cold start that writes a file and maps it back (tt_transformers caches K and V of every layer under one name), or the next start reading the files the cold start wrote | build the all-zero KV tensors without a cache file (`cache_file_name=None`), and have the image's entrypoint copy the `.tensorbin` files written since the last start onto new files once before the server starts (a copy loads normally); an already stuck cache recovers the same way |
| a member loads another member's config or weights (e.g. Music 3 reads S2 Pro's `config.json`) | a model wrote `os.environ["HF_MODEL"]` while loading; the host restores only the keys a member declares | the member's adapter sets its own `HF_MODEL` while it loads and restores the old value |
| a clean check re-downloads every weight, or a "fresh" check serves an old revision | `XDG_CACHE_HOME` moves the HF cache, but tt-model keeps its own state and compiled caches under `~/.cache/tt-model` | for a clean check use a fresh `HOME` for tt-model; to keep weights, point `HF_HOME` at the existing HF cache |
| a member reports `IncompleteSnapshotError` offline after a clean pull | the package's weight ignore patterns skip a file the member's loader checks for | pin that member's weights without ignore patterns |
| speech-to-text returns empty text after the boot | releasing traces between warmups freed the model's staging buffers | re-create the staging buffers after the release (adapter fix) |
| greedy output differs between solo and group | the baseline was taken without the group's fit hooks, or a late compile corrupted a trace | retake the baseline with the hooks; if it persists, check `compiles_after_capture` and keep the logs |
| the group stops when one member's server dies | by design: a container that is up always serves every member | fix the member; `tt-model logs` shows which one ended |
| `unsupported kind 'cohost'` from `tt-model serve` | the installed tt-model predates the cohost kind | install a tt-model that has it |
